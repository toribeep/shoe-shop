# ShoeShop — система оформления заказов обуви

Учебный проект: десктопное приложение для работы с каталогом обуви и оформления заказов.

## Возможности

- просмотр каталога обуви;
- отображение информации о товарах;
- создание и редактирование товаров;
- оформление и управление заказами;
- работа с данными пользователей.

## Требования

- Python 3.13;
- PostgreSQL;
- библиотеки из файла `requirements.txt`.

## Установка и запуск

1. Клонировать репозиторий:

   `git clone <адрес репозитория>`

2. Создать виртуальное окружение:

   `python -m venv .venv`

3. Активировать окружение в Git Bash:

   `source .venv/Scripts/activate`

4. Установить зависимости:

   `pip install -r requirements.txt`

5. Создать базу данных PostgreSQL и настроить параметры подключения в `config.py`.

6. Запустить приложение:

   `python main.py`

## Структура репозитория

- `main.py` — точка входа в приложение;
- `auth_window.py` — окно авторизации;
- `database.py` — работа с базой данных;
- `models.py` — модели данных;
- `resources/` — изображения и другие ресурсы;
- `data/` — файлы с данными;
- `create_tables.sql` — скрипт создания таблиц базы данных;
- `requirements.txt` — список зависимостей.

## ER-диаграмма базы данных

ER-диаграмма базы данных проекта представлена в файле `docs/er-diagram.png`.

База данных включает следующие основные таблицы:

- **users** — хранит сведения о пользователях системы.
- **products** — содержит информацию о товарах: артикул, название, цену, категорию, скидку, количество и описание.
- **orders** — хранит сведения о заказах: номер, даты, данные клиента, пункт выдачи и статус заказа.
- **order_items** — содержит состав заказа: номер заказа, артикул товара и количество.
- **pickup_points** — хранит адреса пунктов выдачи заказов.

### Связи между таблицами

Таблица `orders` связана с `order_items` по номеру заказа. Один заказ может содержать несколько позиций.

Таблица `order_items` связана с `products` по артикулу товара. Это позволяет указать товары и их количество в заказе.

Таблица `orders` связана с `pickup_points` по адресу пункта выдачи.

## Запуск PostgreSQL через Docker Compose

1. Установите Docker Desktop и WSL 2.
2. Создайте файл `.env` на основе `.env.example` и задайте свой пароль.
3. Запустите контейнеры: `docker compose up --build -d`
4. Импортируйте структуру БД:
   `docker compose cp create_tables.sql db:/tmp/create_tables.sql`
   `docker compose exec db psql -U shoe_user -d shoe_store -f /tmp/create_tables.sql`
5. Заполните данными: `python insert_data.py`
6. Приложение подключается по адресу `localhost:5433` (настройки в `config.py`).
7. Остановка: `docker compose stop`.

## Постоянное хранение и сети

### Постоянное хранение данных PostgreSQL

Для сохранения данных PostgreSQL при пересоздании контейнера используется именованный том Docker `db_data`, подключённый к каталогу `/var/lib/postgresql/data`.

Том создаётся автоматически при запуске проекта командой `docker compose up -d`. Данные в нём сохраняются независимо от жизненного цикла контейнера.

### Создание резервной копии

Для создания резервной копии базы данных используется команда:

```powershell
docker compose exec db pg_dump -U shoe_user -d shoe_store -f /tmp/backup.sql
docker compose cp db:/tmp/backup.sql ./backups/backup.sql
```

### Восстановление базы данных

Сначала файл резервной копии копируется в контейнер:

```powershell
docker compose cp ./backups/backup.sql db:/tmp/restore.sql
```

Затем выполняется восстановление:

```powershell
docker compose exec db psql -v ON_ERROR_STOP=1 -U shoe_user -d shoe_store -f /tmp/restore.sql
```

### Запуск проекта

Для запуска контейнеров:

```powershell
docker compose up -d
```

Для проверки состояния:

```powershell
docker compose ps
```

Для проверки подключения к базе данных:

```powershell
docker compose run --rm db-check
```

Для остановки контейнеров:

```powershell
docker compose down
```

**Внимание!** Не используйте команду `docker compose down -v` без необходимости: параметр `-v` удаляет именованные тома, в том числе `db_data`, что может привести к потере данных PostgreSQL.

### Сетевая конфигурация

Для взаимодействия сервисов используется пользовательская сеть Docker `shoe-backend` с драйвером `bridge`.

- PostgreSQL внутри сети доступен по адресу `db:5432`.
- Диагностический сервис `db-check` подключается к PostgreSQL по имени `db`.
- Приложение, запущенное в Windows, подключается к базе через `localhost:5433`.
- Порт PostgreSQL опубликован только на локальном интерфейсе `127.0.0.1:5433`.

Пользовательская сеть обеспечивает взаимодействие контейнеров по именам сервисов, а именованный том обеспечивает сохранность данных при пересоздании контейнеров.
